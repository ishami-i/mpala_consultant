# Mpala Consultant

Website and project-intake system for Mpala Consultant, a construction, land and consultancy company in Rwanda (TIN 156496048).

Clients describe their project on the website. The company gets a short email (name and budget) and opens the dashboard for everything else.

## What it does

- **Public website:** home page with About, Services, Experience and a "Tell us about your project" form. Light and dark mode, works on phones.
- **Project form:** name, email, phone, UPI (land parcel ID), location (province, district, sector), budget (RWF) and a description. The project is saved first; emails are sent after.
- **Emails:** the company receives only the client's name, the budget and a link to the dashboard. The client receives a thank-you.
- **Admin dashboard (`/admin`):** sign in, see all projects, open one to read everything the client sent, filter by status and change it (`new`, `reviewing`, `contacted`, `closed`).
- **API with Swagger UI:** interactive documentation at `/api/docs`.
- **Databases:** SQLite for local testing (default), MySQL for deployment.

## Quick start

You need **Python 3** and **Node.js with npm**. Nothing else for local use.

```bash
chmod +x run.sh
./run.sh
```

The first run installs the packages, creates the database, adds missing keys to `backend/.env` and asks you for the admin email and password. After that it starts everything:

| What | Address |
|---|---|
| Website | http://localhost:5173 |
| Dashboard | http://localhost:5173/admin |
| API | http://localhost:5000/api |
| Swagger UI | http://localhost:5000/api/docs |

Press **Ctrl+C** to stop. Logs are in `.run/backend.log` and `.run/frontend.log`.
`./run.sh stop` stops the Docker MySQL container, if the script started one.

## Configuration

Settings live in `backend/.env`. `run.sh` adds the ones it can; never commit this file.

| Key | Meaning | Default |
|---|---|---|
| `DB_ENGINE` | `sqlite` or `mysql` | `sqlite` |
| `SQLITE_PATH` | SQLite file location | `backend/database/mpala.sqlite3` |
| `DB_HOST`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` | MySQL login (only when `DB_ENGINE=mysql`) | |
| `JWT_SECRET_KEY` | Secret that signs login tokens. Use a long random value. | generated by `run.sh` |
| `ADMIN_EMAILS` | Comma-separated emails allowed to open the dashboard | set at first run |
| `COMPANY_EMAIL` | Where "new project" emails go | |
| `DASHBOARD_URL` | Dashboard address used in the email link | `http://localhost:5173/admin` |
| `MAIL_SERVER`, `MAIL_PORT`, `MAIL_USE_TLS` | SMTP server (`MAIL_USE_TLS=True` for port 587) | port 587 |
| `MAIL_USERNAME`, `MAIL_PASSWORD` | SMTP login (for Gmail use an app password) | |
| `BACKEND_PORT` | API port | `5000` |

Without the email settings, projects are still saved and appear in the dashboard; only the emails are skipped.

## Changing the website content

- **Company name, TIN, years of experience:** `src/data/company.js`.
- **Contact details:** `src/data/contact.js`. Fill in email, phone, WhatsApp (digits only), YouTube and social links. Empty values are hidden.
- **Services:** the list at the top of `src/components/services.jsx`.
- **Other text:** `src/components/aboutCompany.jsx`, `experiences.jsx` and the hero in `src/pages/home.jsx`.
- **Colours and fonts:** the variables at the top of `src/site.css`.

## How a project moves through the system

1. The client submits the form (`POST /api/projects`). The project is saved with status `new`.
2. The company gets an email with the name, the budget and a link like `/admin#project-12`.
3. The link opens the dashboard on that project. An admin reads the details, contacts the client and updates the status.

Only emails listed in `ADMIN_EMAILS` get admin access. Other registered users are refused (403) on the admin routes.

## API

Full interactive documentation: `/api/docs`. Summary:

| Method and path | Access | Purpose |
|---|---|---|
| `POST /api/register` | public | Create a user |
| `POST /api/login` | public | Get a token |
| `POST /api/projects` | public | Client submits a project |
| `GET /api/admin/projects` | admin | List projects (summary) |
| `GET /api/admin/projects/<id>` | admin | Everything about one project |
| `PATCH /api/admin/projects/<id>/status` | admin | Set status |

Admin requests send `Authorization: Bearer <token>`.

## Databases

**SQLite (local testing):** automatic, one file, nothing to install.

**MySQL (deployment):** in `backend/.env` set

```
DB_ENGINE=mysql
DB_HOST=...
DB_USER=...
DB_PASSWORD=...
DB_NAME=mpala
```

then run `./run.sh` or `python backend/init_db.py` once to create the tables. If MySQL is not running locally and Docker is installed, `run.sh` starts a MySQL container for you.

## Applying an update

./apply_update.sh mpala_update.zip ~/projects/mpala_consultant

## Deploying

This repository is set up for development. Before going live:

1. Use MySQL (`DB_ENGINE=mysql`) and a strong `JWT_SECRET_KEY`.
2. Run the API with a production server such as `gunicorn app:app` from `backend/`, not `python app.py`. Put it behind HTTPS.
3. Build the frontend with `npm run build`, with `VITE_API_URL` pointing at your public API address (for example in `.env.production`), and serve the `dist/` folder.
4. Set `DASHBOARD_URL` to your real dashboard address and fill in the `MAIL_*` and `COMPANY_EMAIL` values.
5. **Close open registration.** `POST /api/register` is public. The admin check protects client data, but you should remove or protect that route once your admin account exists.
6. Keep `backend/.env` and the SQLite file out of git: add `backend/.env`, `.env.local`, `.run/` and `backend/database/*.sqlite3` to `.gitignore`.

## Troubleshooting

| Problem | What to do |
|---|---|
| `port 5000 is already in use` | On macOS, AirPlay uses port 5000. Set `BACKEND_PORT=5001` in `backend/.env`. Also stop any backend you started by hand. |
| `port 5173 is already in use` | Stop the other Vite dev server. |
| `frontend did not start` | Look at `.run/frontend.log`. The first start can take 20 seconds or more. |
| Dashboard says "This account is not an admin" | The login email is not in `ADMIN_EMAILS`. Add it, then restart `./run.sh`. |
| No emails arrive | Set `COMPANY_EMAIL` and the `MAIL_*` values. Check `.run/backend.log` for "Email failed". |
| Cannot connect to MySQL | Check `DB_HOST`, `DB_USER`, `DB_PASSWORD` and that MySQL is running. |
| Forgot the admin password | Delete the user row in the database, or run `run.sh` again on an empty users table to create a new admin. |
