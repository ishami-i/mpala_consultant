# Mpala Consultant

Website and project-intake system for Mpala Consultant, a construction, land and consultancy company in Rwanda (TIN 156496048).

Clients describe their project on the website. The company gets a short email (name and budget) and opens the dashboard for everything else.

## What it does

- **Public website:** home page with About, Services, Experience and a "Tell us about your project" form. Light and dark mode, works on phones.
- **Project form:** name, email, phone, UPI (land parcel ID), location (chosen in three steps: province, then district, then sector), the service needed, budget (RWF) and a description. The project is saved first; emails are sent after.
- **Emails:** the company receives only the client's name, the budget and a link to the dashboard. The client receives a thank-you.
- **Admin dashboard (`/admin`):** sign in to three tabs. **Overview** counts projects in total and in the last 30 days (with growth against the 30 days before), per month for the last year, per province and per service, and by status. **Projects** lists every project: open one to read everything the client sent, change its status (`new`, `reviewing`, `contacted`, `closed`) or delete it. **Gallery** manages the photos.
- **Photo gallery:** one gallery per service (construction and architecture first). Admins upload photos in the dashboard (**Gallery** tab); they appear on the public `/gallery` page at once, with filters per service and a full-size viewer. A "View gallery" link appears under a service on the home page as soon as it has photos.
- **API with Swagger UI:** interactive documentation at `/api/docs`.
- **Databases:** SQLite for local testing (default), MySQL for deployment.

## Quick start

You need **Python 3** and **Node.js with npm**. Nothing else for local use.

```bash
chmod +x run.sh
./run.sh
```

The first run installs the packages, creates the database, adds missing keys to `backend/.env` and asks you for the admin email and password. After that it starts everything:

| What | Address |
|---|---|
| Website | http://localhost:5173 |
| Dashboard | http://localhost:5173/admin |
| API | http://localhost:5000/api |
| Swagger UI | http://localhost:5000/api/docs |

Press **Ctrl+C** to stop. Logs are in `.run/backend.log` and `.run/frontend.log`.
`./run.sh stop` stops the Docker MySQL container, if the script started one.

## Configuration

Settings live in `backend/.env`. `backend/.env.example` lists every key with comments: copy it to `backend/.env` and fill it in. `run.sh` adds the keys it can for local use. Never commit `backend/.env`.

| Key | Meaning | Default |
|---|---|---|
| `DB_ENGINE` | `sqlite` or `mysql` | `sqlite` |
| `SQLITE_PATH` | SQLite file location | `backend/database/mpala.sqlite3` |
| `DB_HOST`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` | MySQL login (only when `DB_ENGINE=mysql`) | |
| `JWT_SECRET_KEY` | Secret that signs login tokens. Use a long random value. | generated by `run.sh` |
| `ADMIN_EMAILS` | Comma-separated emails allowed to open the dashboard | set at first run |
| `ALLOW_REGISTRATION` | `true` lets anyone create a user via `/api/register`. Use `false` in production. | `true` (deploy.sh sets `false`) |
| `COMPANY_EMAIL` | Where "new project" emails go | |
| `PUBLIC_EMAIL` | The address clients see in emails and reply to | `info@<your domain>` |
| `SITE_URL` | Website address used for the links in emails | `DASHBOARD_URL` without `/admin` |
| `MAIL_FROM_NAME` | Name shown next to the sender address | `Mpala Consultant` |
| `DASHBOARD_URL` | Dashboard address used in the email link | `http://localhost:5173/admin` |
| `MAIL_SERVER`, `MAIL_PORT`, `MAIL_USE_TLS` | SMTP server (`MAIL_USE_TLS=True` for port 587) | port 587 |
| `MAIL_USERNAME`, `MAIL_PASSWORD` | SMTP login (for Gmail use an app password; for Cloudflare: `api_token` and an API token) | |
| `MAIL_USE_SSL` | `True` for port 465 (Cloudflare). Use it instead of `MAIL_USE_TLS`. | `False` |
| `MAIL_FROM` | Address in the From line. Needed when the login is not an email address. | `MAIL_USERNAME` |
| `BACKEND_PORT` | API port | `5000` |
| `UPLOAD_DIR` | Folder for gallery photos | `backend/uploads/gallery` |
| `MAX_UPLOAD_MB` | Largest single photo, in MB | `8` |

Without the email settings, projects are still saved and appear in the dashboard; only the emails are skipped.

## Admin login

Create an admin (or reset a password) in the terminal, from the project folder:

```bash
cd backend
venv/bin/python create_admin.py you@example.com
```

Then make sure the email is in `ADMIN_EMAILS` in `backend/.env` and restart the app. Details and troubleshooting: [DEPLOYMENT.md](DEPLOYMENT.md).

## Changing the website content

- **Company name, TIN, years of experience, address and logo:** `src/data/company.js`. To use your own logo, put the image in `public/` and change `logo` there (the default `public/logo.svg` is a placeholder).
- **Contact details:** `src/data/contact.js`. Fill in email, phone, WhatsApp (digits only), YouTube and social links. Empty values are hidden.
- **Services:** the list in `src/data/services.js`. The first two (architectural study and construction) are the main business and are shown larger. Services marked `paid: true` show a "Paid service" tag and a note in the project form that payment is arranged with the team, not on the website. The same list feeds the "Service you need" choice in the form.
- **Other text:** `src/components/aboutCompany.jsx`, `experiences.jsx` and the hero in `src/pages/home.jsx`.
- **Colours and fonts:** the variables at the top of `src/site.css`.

## Gallery

1. Sign in at `/admin` and open the **Gallery** tab.
2. Choose the service, add an optional caption, select one or more photos (JPG, PNG or WebP) and click **Upload photos**.
3. The photos are saved in `backend/uploads/gallery/` and appear on `/gallery` and `/gallery/<service>` immediately. Delete a photo from the same tab.

Notes:
- Only the file's real content is trusted: anything that is not a JPG, PNG or WebP is refused. Photos are stored under random names.
- Resize very large camera photos before uploading (about 2000 px wide is plenty for the web); the limit is `MAX_UPLOAD_MB` each.
- The services that have a gallery are the list `GALLERY_CATEGORIES` in `backend/config.py`. To add one, add a line there and, to get the "View gallery" link, use the same slug in `src/components/services.jsx`.
- Add `backend/uploads/` to `.gitignore` and include it in your backups.

## How a project moves through the system

1. The client submits the form (`POST /api/projects`). The project is saved with status `new`.
2. The company gets an email with the name, the budget and a link like `/admin#project-12`.
3. The link opens the dashboard on that project. An admin reads the details, contacts the client and updates the status.

Only emails listed in `ADMIN_EMAILS` get admin access. Other registered users are refused (403) on the admin routes.

## API

Full interactive documentation: `/api/docs`. Summary:

| Method and path | Access | Purpose |
|---|---|---|
| `POST /api/register` | public | Create a user |
| `POST /api/login` | public | Get a token |
| `POST /api/projects` | public | Client submits a project |
| `GET /api/admin/projects` | admin | List projects (summary) |
| `GET /api/admin/projects/<id>` | admin | Everything about one project |
| `PATCH /api/admin/projects/<id>/status` | admin | Set status |
| `DELETE /api/admin/projects/<id>` | admin | Delete a project |
| `GET /api/admin/stats` | admin | Overview numbers (totals, per province, per service, per month, growth) |
| `GET /api/gallery/categories` | public | Galleries with photo counts |
| `GET /api/gallery` | public | List photos (`?category=slug`) |
| `GET /api/uploads/<file>` | public | A photo file |
| `POST /api/admin/gallery` | admin | Upload photos (form data: `category`, `caption`, `files`) |
| `DELETE /api/admin/gallery/<id>` | admin | Delete a photo |

Admin requests send `Authorization: Bearer <token>`.

## Databases

**SQLite (local testing):** automatic, one file, nothing to install.

**MySQL (deployment):** in `backend/.env` set

```
DB_ENGINE=mysql
DB_HOST=...
DB_USER=...
DB_PASSWORD=...
DB_NAME=mpala
```

then run `./run.sh` or `python backend/init_db.py` once to create the tables. If MySQL is not running locally and Docker is installed, `run.sh` starts a MySQL container for you.

## Applying an update

Updates come as a zip. Preview, then apply:

```bash
./apply_update.sh -n mpala_update.zip ~/projects/mpala_consultant   # dry run
./apply_update.sh mpala_update.zip ~/projects/mpala_consultant
```

Changed files are backed up in `.update_backup_<timestamp>/` inside the project.

## Deploying

The full step-by-step guide, including server setup, MySQL, nginx, HTTPS, updates, backups and troubleshooting, is in **[DEPLOYMENT.md](DEPLOYMENT.md)**. In short, `deploy.sh` prepares a Linux server (MySQL, nginx, systemd). On the server:

```bash
cp backend/.env.example backend/.env      # then fill it in: DB_ENGINE=mysql, MySQL login,
                                          # JWT_SECRET_KEY, ADMIN_EMAILS, COMPANY_EMAIL, MAIL_*
chmod +x deploy.sh
./deploy.sh --domain example.com
```

The script:

1. Refuses to continue while any setting is missing or still a placeholder, and lists what to fix.
2. Sets `ALLOW_REGISTRATION=false` (and refuses `true`) and points `DASHBOARD_URL` at your domain.
3. Installs the backend packages and the production web server (gunicorn), creates the MySQL tables, and creates the first admin (it asks in a terminal, or reads `ADMIN_SEED_EMAIL` and `ADMIN_SEED_PASSWORD`).
4. Builds the website into `dist/` for `https://example.com/api`.
5. Writes `deploy/mpala-api.service` (systemd) and `deploy/nginx-mpala.conf`, then prints the exact `sudo` commands to publish the files, start the API service, enable nginx and get an HTTPS certificate.

`./deploy.sh start` runs the API on `127.0.0.1:<BACKEND_PORT>`; this is what the systemd service runs. nginx serves the website and forwards `/api/` to it.

To publish a new version: `git pull`, run `./deploy.sh --domain example.com` again, copy `dist/` to `/var/www/mpala`, and `sudo systemctl restart mpala-api`.

Also keep `backend/.env`, `.env.local`, `.run/`, `deploy/` and `backend/database/*.sqlite3` out of git (`.gitignore`).

## Troubleshooting

| Problem | What to do |
|---|---|
| `port 5000 is already in use` | On macOS, AirPlay uses port 5000. Set `BACKEND_PORT=5001` in `backend/.env`. Also stop any backend you started by hand. |
| `port 5173 is already in use` | Stop the other Vite dev server. |
| `frontend did not start` | Look at `.run/frontend.log`. The first start can take 20 seconds or more. |
| Dashboard says "This account is not an admin" | The login email is not in `ADMIN_EMAILS`. Add it, then restart `./run.sh`. |
| No emails arrive | Set `COMPANY_EMAIL` and the `MAIL_*` values. Check `.run/backend.log` for "Email failed". |
| Cannot connect to MySQL | Check `DB_HOST`, `DB_USER`, `DB_PASSWORD` and that MySQL is running. |
| Forgot the admin password | Delete the user row in the database, or run `run.sh` again on an empty users table to create a new admin. |
